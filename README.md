# キャラクター外見設計工房

日本語UIで1人の人間型キャラクター本人の顔、髪、肌、身体つきを構造的に設計し、画像生成AI向けの英語タグ型プロンプトへ変換する静的Webアプリです。

公開URL: <https://nyuriwossan.github.io/character-appearance-prompt-workshop/>

## 主な機能

画面上部のタブで2つの画面を切り替えます。どちらも同じ外見データを使い、切り替えても入力内容や保存データは変わりません。

| タブ | 内容 |
| --- | --- |
| 外見設計（初期表示） | 部分プリセット、外見設計、高度な設定（Markdown・HEX）、設計チェック、通常・高度なプロンプト出力、保存・復元 |
| 顔ID・LoRA | 「同じ顔を、何度でも。」の管理画面、固定／可変／除外タグ、顔IDの保存・適用・比較、顔ID・LoRA用プロンプト、顔確認・学習画像の出力 |

- 1,162件の外見候補（部位別の色候補を含む）を、基本・顔骨格・目・眉鼻口・髪・肌・身体・固有特徴・印象へ分類
- 平行眉、困り眉、目のハイライト、虚ろな目、生気のない目、ピアスの位置・数・形状・扱い
- 顔立ち、目元、眉、髪型、体格、配色の部分プリセット114件
- 6カテゴリ切替、レスポンシブカード、「もっと見る」による探しやすいプリセットUI
- プリセット適用前に、新規設定・既存値の変更・影響項目数を日本語で確認
- 選択中の日本語タグを常時確認し、タグから直接解除
- 短縮プロンプト、詳細プロンプト、他工房と合体しやすい素体プロンプト、日本語まとめ、基本の外見、アレンジ項目を生成
- 安全な画角語を使う顔確認用と、頭から足先までを強調する身体確認用プロンプト
- hard / warning / info / suggestion の4段階の設計チェックと、明確な場合だけのパッチ型修正
- 下書き自動保存、名前付き保存、読込、複製、削除
- 編集中データと全保存データのJSON書き出し、旧形式の正規化、壊れたJSONの安全な拒否
- 320px級からPCまでのレスポンシブUI、スマホ用に整理したヘッダー、44pxタップ領域、目立つ全項目リセット、固定の「上へ戻る」、iOS向けコピー代替処理

通常の外見出力は人物の特徴に限定します。顔確認・学習画像用の出力には角度、表情、照明、背景のテンプレートを追加します。部位診断の数字は設定数の目安で、生成品質の採点ではありません。

## 髪型参考一覧

「外見設計」タブの「髪型・カットの基本形」にある **髪型の参考画像を見る** から、髪型の参考イラストを一覧で見比べられます（`hair-reference.html`）。名前を確認したら「外見設計に戻る」またはブラウザの「戻る」で元の画面へ戻り、従来の選択ボタンから選びます。参考一覧を見るだけでは外見データは変わりません。

- 現在は第1弾の9種類（クロップ／ピクシーカット／マッシュ／レイヤーショート／ボブ／ロングボブ／ウルフカット／シャギーカット／ストレートロング）を掲載しています。残りの38種類は「画像準備中の髪型」として名前だけを表示します。
- 表示名と並び順は、外見設計の選択肢と同じ辞書（`data/*.js`）から取ります。
- 戻った時は、外見データ・選んだ髪型・開いていたアコーディオン・画面の位置を保ちます。Safariが前の画面をそのまま戻せない場合は、自動保存したデータを読み込み、開いていたアコーディオンと位置だけを復元します。
- 参考画像は髪型の違いを示す模式的なイラストで、画像生成AIで同じ髪型が再現されることを保証するものではありません。

### 画像の追加方法

```text
assets/hair-reference/
  manifest.json
  images/
    crop.webp ...
```

1. 画像を `assets/hair-reference/images/<optionId>.webp`（正方形）として置きます。
2. `manifest.json` に1件追加します。`fieldId` は `baseCut`、`optionId` は `data/hair.js` などにある既存の選択肢IDです。

```json
{ "fieldId": "baseCut", "optionId": "hime", "labelJa": "姫カット", "descriptionJa": "短い説明", "image": "images/hime.webp" }
```

辞書にないID・ほかの項目・不正な画像パス・重複は表示しません。`labelJa` が辞書と違う場合は辞書の名前を表示します。追加後は `npm test` の対応チェック（9件の一覧や件数の期待値）も合わせて更新してください。

## 高度な設定（Markdown出力・HEXカラー指定）

「外見設計」の冒頭にある **高度な設定** をONにすると、次の2つを個別に有効化できます。初期値はOFFで、OFFの間は従来の画面・操作・出力のままです。

| 高度な設定 | Markdown | HEX | 動作 |
| --- | --- | --- | --- |
| OFF | 任意 | 任意 | 従来機能のみ |
| ON | OFF | OFF | 従来機能のみ |
| ON | ON | OFF | Markdown出力を追加 |
| ON | OFF | ON | HEX入力と「タグ＋HEX」出力を追加 |
| ON | ON | ON | タグ＋HEX／Markdown／Markdown＋HEX |

どちらも**実験的な補助機能**です。MarkdownやHEXコードがどの画像生成モデルでも解釈されると確認できているわけではなく、PixAI・NovelAIなどでの効き方はモデルや生成条件によって異なります。生成結果が良くなるとは限らないため、従来のプロンプトと見比べながら使ってください。従来の短縮・詳細・素体プロンプトや顔ID・LoRA用の出力は、高度な設定の状態にかかわらず変わりません。

### 使い方

1. 「外見設計」冒頭のスイッチで高度な設定をONにし、使いたい機能にチェックを入れます。
2. HEXを有効にすると、瞳・髪・肌の色の項目に「ピッカー」ボタンとHEX入力欄が表示されます。
   - **ピッカー**：彩度×明るさのエリアと、色相・彩度・明るさのスライダーで調整し、「この色を設定」で確定します。HEX欄と相互に同期し、端末標準のカラーピッカーも呼び出せます。色名を選んでいる場合は、その色見本を開始位置にします（「色名の色見本に合わせる」でも戻せます）。
   - **HEX直接入力**：`#RRGGBB` のほか、`#`なしの6桁、3桁（`#ABC`）、小文字、全角に対応し、`#RRGGBB` の大文字へ正規化します。入力途中は反映せず、不正な値は保存・出力しません。「解除」または空欄で未設定に戻せます。
3. 出力欄の「高度な出力」で形式（タグ＋HEX／Markdown／Markdown＋HEX）と範囲（詳細／短縮／素体）を切り替え、コピーします。

### 色名とHEXの併記

HEXは色名を置き換えず、色名のあとに併記します。

```text
silver hair (#C8CCD6), blue-gray eyes (#748DA8), fair skin (#F4DED8)
```

- 対象は、瞳（基本色・左目・右目・虹彩の内側／外側・中央リング・部分的な異色）、髪（基本色・根元・毛先・メッシュ・インナー・内側の層・左側・右側・前髪）、肌の基本色の17か所です。
- 出力されるのは**自分で設定したHEXだけ**です。高度な設定をONにしただけでは、辞書の色見本がHEXとして出力されることはありません。
- 色名が未選択でHEXだけ設定した場合は、`hair color (#C8CCD6)` のように部位名で出力し、近い色名を自動では決めません。
- 既存の優先順位はそのままです。左右の瞳色を両方指定すると基本色とそのHEXは出力せず、グラデーションで根元と毛先を両方指定すると基本色は重ねません。「単色」の間は部位の髪色とそのHEXを出力しませんが、設定値は保持します。「オッドアイ」を基本色に選んでいる間は基本色のHEXを使いません。
- 出力されていないHEXは、各入力欄と高度な設定内の一覧に「保持のみ」と表示します。
- 左右の基準の注記が付く瞳色では、括弧を2つ並べず `blue left eye (#3366CC, character's own left/right)` のように1つにまとめます。HEXを設定していない場合や従来の出力は `blue left eye (character's own left/right)` のままです。
- 色名とHEXの色味が大きく離れている場合（例：青髪に赤系のHEX）は注意を表示しますが、意図した配色の可能性があるため自動修正はしません。

### Markdown出力

選択した項目を、既存のフィールド・カテゴリ情報をもとに見出しごとに整理した英語Markdownです。詳細プロンプトのカンマを改行に置き換えたものではありません。

```text
## Eyes
- Eye shape: almond-shaped eyes
- Iris color: blue-gray eyes (#748DA8)
## Hair
- Hair length: waist-length hair
- Hair color: silver hair (#C8CCD6)
## Skin
- Skin tone: fair skin (#F4DED8)
```

見出しは `Character / Face / Eyes / Eyebrows / Nose / Mouth / Hair / Skin / Body / Identifying Features / Accessories / Overall Impression` の固定順です。未選択の項目と空の見出しは出力しません。自由入力タグは対応する見出しの `Additional` に入り、選択タグと同じ語は整理します。顔IDで「除外」にしたタグは含めません。左右の「本人／画面」基準、メガネ・ピアスの扱い、年齢語句の置換は従来の出力と同じです。

### 保存・復元

- HEXは外見データの一部（`hexColors`）として、自動保存・名前付き保存・複製・JSON書き出し／読込に含まれます。色名を変更・解除してもHEXは残ります（不要なら「解除」または「HEXをすべて解除」）。「全項目リセット」ではHEXも初期化します。
- 高度な設定・Markdown・HEXのON/OFFと、高度な出力で選んだ形式は、この端末の表示設定として別のキー（`caw_ui_settings_v1`）に保存します。OFFにしても入力済みのHEXは消えず、JSONにも含まれます。別の端末でJSONを読み込んだ場合は、その端末で高度な設定をONにするとHEXが表示されます。
- 保存スキーマは `0.3` です。`hexColors` を持たない従来の `0.1` / `0.2` のJSONや保存データはそのまま読み込めます。未知の部位IDや不正なHEXは読み込み時に捨て、他の内容には影響しません。既存のlocalStorageキーは変更していません。
- 顔IDには**瞳のHEXだけ**を保存します。顔IDを適用すると瞳のHEXが復元され、髪・肌のHEXは残ります。「顔だけリセット」は瞳のHEXだけを消します。顔IDの比較では瞳のHEXの差異も表示します。HEXを持たない従来の顔IDも読み込めます。

## 顔ID・LoRA対応

### 色の詳細・髪型の追加

瞳の基本色は40色、髪の基本色は48色から選択できます。「目・瞳」の詳細では左目／右目、虹彩の内側／外側、中央リング、部分的な異色を設定できます。「髪色・髪質」の詳細では根元／毛先、メッシュ、インナー、内側の層、本人基準の左右、前髪の色を設定できます。色見本は各英語色名の目安です。

詳細は通常折りたたみ、オッドアイ・特殊な瞳配色・複数髪色を選ぶと開きます。手動で閉じた状態も保存します。左右の瞳色は基本色より優先し、片目のみ指定した場合はもう片目へ基本色を使います。左右の髪色を両方指定した場合と、グラデーションの根元／毛先を両方指定した場合は、全体の基本色を重ねません。「単色の髪」の間は部位の髪色を出力しませんが、選択データは保持します。

髪型の基本形は15種類から47種類、髪型プリセットは21件から37件へ拡張しました。姫カット、クラゲカット、バタフライカット、ツインテール、ハーフアップ、シニヨン、編み込み、コーンロウなどを追加しています。

年齢選択の英語出力は `young person` / `grown person` / `mature person` を使用します。従来の年齢選択IDは保持するため、保存済みデータの読み込み後も置き換わった出力になります。自由入力にある単独の `adult`（複数形、`adlut` を含む）、`bust`、`bust up`、`bust portrait` も英語出力時に置換し、自由入力の保存内容は維持します。LoRAトリガーワードは固有の識別文字列なので自動変更しません。PixAIアプリの実際の判定結果は検証していません。

- 顔骨格・目・眉鼻口・顔のほくろと傷・メガネとピアスを、髪・肌・身体と分けて顔IDに保存
- 顔ID名、メモ、トリガーワード、固定度の管理メモ、本人／画面の左右基準、反転許可を保持
- 選択した顔タグの日本語・英語・識別度を一覧表示し、固定／可変／除外を切替
- 通常の英語出力では固定と可変を使用し、除外をネガティブ側へ分離。旧データは全タグを固定として扱い、従来の出力を維持
- 顔だけ適用／リセット、別ID保存、上書き保存ごとのバージョン更新、顔JSON・全顔IDバックアップ
- 相反候補は警告し、タグ解除または「両方残す」を選択可能。大きさ・鼻長・唇厚など既存の単一選択軸はそのまま維持し、英語追加タグと競合する場合もチェック
- 輪郭・目・眉・鼻・口・識別点・左右差の固定タグ数と、不足する部位を診断
- 顔固定／可変／ネガティブ、PixAI1行、正面／斜め／横顔／微笑み／目元の学習画像作成用プロンプト
- ほくろ・傷、左右反転、3面図の顔確認モード。文字・透かし・複数人等は専用ネガティブ欄へ出力
- 現在の顔と保存顔、保存した2つの顔をタグ・レイヤー・固定プロンプト・トリガー・版で比較
- 使用／学習モデル、LoRA、代表画像・角度別画像、学習から除く画像、Seed等のメモ

顔IDを適用しても髪・肌・体格と首／鎖骨のほくろ・傷は残します。旧データでは顔と身体のほくろ・傷が大きさ等を共有するため、身体の特徴がある場合は共通項目を身体側の設定で保持します。自由入力の「固有特徴」タグは顔か身体か判別できないため顔IDに含めません。顔の自由タグは「顔」「目」の追加タグ欄をご利用ください。

顔IDの `fixedTags` / `variableTags` / `excludedTags` は `fieldId:optionId`（追加タグは `custom:group:tag`）の参照です。顔JSONには顔だけの `appearance` と `customTags` も保存します。選択IDを正本にすることで英語辞書の修正にも対応します。保存時は `schemaVersion: "0.3"`（`0.2` に瞳の `hexColors` を追加）とし、従来の `0.1` / `0.2` や `selections` 形式を自動移行します。従来の下書き・設計保存のlocalStorageキーは変更しません。全保存バックアップには `faceProfiles` も含まれます。

固定度と生成パラメータは管理用メモです。画像生成やLoRA学習を実行する機能、画像解析、PixAIとのAPI接続はありません。学習用出力は画像を生成するためのプロンプトで、画像の内容を記述する学習キャプションとは用途が異なります。3面図は確認用として、学習には各ビューを切り出して利用してください。

参考： [PixAIのLoRA学習ガイド](https://blog.pixai.art/en/train-lora-on-pixai/)、[キャラクターの一貫性ガイド](https://blog.pixai.art/en/pixai-character-consistency-3-beginner-methods/)。モデルや推奨条件は公式ガイドで確認してください。

## 役割分担

```text
入力UI
  ↓ selection / patch
state.js
  ↓
normalizer.js
  ├─ generator.js → 短縮・詳細・日本語・確認用出力
  │    └─ advanced-output.js → タグ＋HEX・Markdown（高度な出力）
  ├─ advisor.js   → 4段階の設計チェックと修正patch
  └─ storage.js   → 自動保存・複数保存・JSON
```

`hex-color.js` はHEXの正規化・保存値の検証・色名との優先順位を、`advanced-ui.js` は高度な設定のスイッチ・カラーピッカー・高度な出力欄を担当します。`app.js` は画面描画とイベント接続に限定し、プリセットの分類・適用差分計算は `preset-ui.js`、大量の候補は `data/` へ分離しています。生成済みプロンプトではなく選択IDを保存の正本にするため、辞書の修正や将来の移行へ対応できます。

## 使い方

1. 「部分プリセット」の見出しをタップして開き、6カテゴリを切り替え、必要なら「もっと見る」で候補を展開します。
2. カードの説明と項目数を確認し、適用前の変更内容を見てから開始地点として適用します。
3. 「外見設計」タブのアコーディオンから必要な項目だけ選びます。
4. 固定バーの日本語タグと「設計チェック」を確認します。
5. 短縮版または詳細版をコピーします。
6. 残したい設計は名前を付けて保存し、定期的にJSONバックアップを書き出します。
7. 顔を固定したいときは「顔ID・LoRA」タブで固定／可変／除外を決め、顔IDとして保存します。適用した顔IDは「外見設計」タブの選択と出力にもすぐ反映されます。

「部分プリセット」は初めは閉じた状態で、見出しまたは「開く」で開閉できます。開閉の状態はこの端末の表示設定（`caw_ui_presets_v1`）として覚え、外見データやJSONには含めません。開閉だけでプリセットが適用されることはありません。

タブは画面上部に固定され、スクロールした位置からでも切り替えられます。タブごとのスクロール位置は切り替えても保持し、初めて開くタブは先頭から表示します。左右キー・Home・Endでも切り替えられます。再読込すると「外見設計」タブから始まります。

編集内容は変更から約0.2秒後に自動保存します。ホーム画面やほかのアプリへ切り替えたとき、ページを閉じたとき、再読込したときは、未保存の変更をその場で保存します（入力途中の設計名と自由入力タグも含みます）。変更がなければ保存は行いません。

保存先は端末のブラウザ内です。ブラウザ履歴、サイトデータ、ストレージを削除すると消える場合があります。重要な設計はJSONバックアップを保管してください。

## ローカル実行

ビルドや依存ライブラリは不要です。`file://` でも表示できますが、保存やコピーを含む確認はローカルサーバー経由を推奨します。

```bash
python -m http.server 8000
```

`http://localhost:8000/` を開きます。

## テスト

Node.js 22以降で実行します。外部パッケージは不要です。

```bash
npm test
```

データ整合性、状態、旧形式正規化、生成、診断、保存、代表キャラクター5例、静的なUI要件を検査します。顔IDの保存／適用／リセット、レイヤー分離、矛盾、左右指定、JSON、共有の身体特徴維持、色の優先順位と保存、年齢語句の置換、追加髪型を検査します。`tests/legacy-fixtures.json` は改修前のmainから取得した6ケース・8種類の出力で、今回要求された年齢語句の置換を除き、従来の出力が一致することを検査します。高度な設定は `tests/advanced-tests.js` で、初期OFFと表示条件、HEXの正規化と拒否、色名との併記、左右の瞳・グラデーション・単色の優先順位、Markdownの見出し順・重複・除外・左右指定、旧JSONの移行と新JSONの往復、顔IDの瞳HEX、そしてHEXを設定しても従来の出力が変わらないことを検査します。`tests.html` ではブラウザのスモークテストも実行できます。

## 既知の制限

- 左右指定、薄い傷、小さなほくろ、リムレス眼鏡、小さなピアスなどはモデルによって反転・省略されます。
- 口元のピアスはモデルによって位置がずれる場合があります。
- MarkdownやHEXコードの解釈はモデルによって異なり、無視されたり、人物以外（背景など）の色に影響したりする場合があります。
- HEXの不一致チェックは色相と明暗の大きな差だけを見る簡易判定です。肌色には辞書の色見本がないため、ピッカーの開始位置と判定には内部の目安色を使います。
- 高度な設定はiPhone Safariの実機では未検証です（Chromeのスマートフォン幅とタッチ操作で確認）。
- 設計チェックは論理的な補助で、生成結果の再現を保証しません。
- 自由入力は英語タグを前提とし、内容の意味判定は行いません。
- 保存はこの端末のブラウザ内だけで、端末間同期はありません。
